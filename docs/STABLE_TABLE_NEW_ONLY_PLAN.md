# 稳定牌桌布局与仅保留新版计划

日期：2026-09-09。本文在本次实现前记录。

## 用户要求与边界

1. 听牌区域无候选时不显示任何文字；有候选时只保留牌及此前要求的牌下余张数，不再显示标题、加载、版本、番数、解释或展开按钮。打后听牌使用弃牌图案、箭头和进张牌说明关系，不用长文字。
2. 同一座位同一小局刷新时保留已显示结果，后台计算；仅当可见牌/张数真正改变时替换。空结果确实更新时清空。换房、换身份、换局、结算及身份校验失败时清空，防止旧手牌串到新上下文。暂时网络失败静默退避重试（1 秒、3 秒，之后每 30 秒）；不把旧候选变成可执行动作。
3. 听牌区域固定尺寸并在内部滚动；牌河、副露、中央状态和操作区域预留稳定空间，溢出在区内滚动，不使页面随摸打牌或提示变化上下跳动。保留窄屏操作与可访问性。
4. 移除旧版入口、查询参数切换、旧版前端页面/状态/API/样式/依赖，以及旧版专属后端控制器、规则、服务、配置和相应测试。通过依赖审计保留新版共用的 Tile 类型及有效基础配置；审计确认旧 Meld 无引用，一并删除。历史文档、备份和房间数据不作为运行代码删除。

## 实施与协作顺序

- 先确认依赖关系，备份本地和服务器被修改/删除的源文件，再删除已证实旧版专属的精确文件。记录删除清单，支持恢复。
- 并行进行听牌静默缓存、牌桌定高布局、旧版前端/后端清理；不同文件分工，集成时检查交叉引用。
- 更新使用文档和隔离浏览器验收夹具，不把测试夹具发布为生产入口。
- 前端单元/组件回归、后端新版与共有代码回归、生产构建；验证旧版 API 不再注册、旧版包不进入新构建。
- 浏览器比较无听牌/有听牌/更新中/相同结果以及少量/大量牌河的关键元素坐标；桌面与窄屏验证，检查溢出与操作可达。
- 发布前备份，检查进行中的房间。无进行中新版真人牌局时切换后端及前端；如不满足安全切换条件则报告待发布，不擅自中断真人对局。清理线上明确旧版专属资源，保留备份及新版可用共享资产。
- 所有测试、发布与删除恢复位置记录在 `STABLE_TABLE_NEW_ONLY_TEST_REPORT.md`。
