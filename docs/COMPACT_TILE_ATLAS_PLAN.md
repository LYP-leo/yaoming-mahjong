# 紧凑牌面图集与无损压缩计划 · 2026-09-08

> 已停用：用户要求停止截图方案，以下仅为历史记录。当前方向见 [上游 SVG 牌面计划](UPSTREAM_TILE_ASSETS_PLAN.md)。

## 目标（编码前记录）

用户要求减少下载量，并保持现有牌面图案不变。当前前端传输整张 2224×759 PNG，共 1,259,949 字节。本轮只优化图片资产与裁切坐标，不改牌面尺寸、字形、颜色、SVG 轮廓、红宝牌滤镜、游戏规则或后端。

## 实施

1. 固定此前验收的 34 张源裁切矩形，保留原始 PNG 供校验和再生成，但不再被正式应用导入。
2. 通过确定性构建脚本原尺寸搬运像素，排成 9 列、4 行紧凑图集；每格最多 118×178，周围保留 2px 原图边缘采样保护区，防止缩放边缘串色。输出 1098×728。源矩形和生成坐标可追溯，不缩放、不锐化、不量化、不重绘。
3. 使用开发依赖 Sharp 比较完整色彩 PNG 与 lossless WebP，选择实际更小且逐像素校验通过的结果。压缩库不进入客户端运行包。
4. 生成图集坐标元数据，共享渲染器维持原显示契约；调整 34 张牌、红五及下游回归断言。新增对所有原裁切区域及保护区的解码像素比较，差异须为零。
5. 本地检查字牌、七筒七索、红五、横置副露和小尺寸。运行图集可重现检查、全量前端测试及构建；检查正式构建只包含紧凑素材，没有原始大图。
6. 更新本地说明与测试文档，服务器先备份源文件/依赖清单/产物，再重复测试和构建。仅发布前端，保留旧哈希资源；核对公网大小、内容类型、缓存及哈希，记录真实下载测量，不将单次速度宣传为保证值。

## 验收

- 34 种牌与既有图案像素一致（包括白板与三元牌值映射），安全保护区完整；不改变暗牌隐私或红五显示行为。
- 新素材小于原始 PNG；报告原大小、新大小和减少比例。
- 后端进程与房间不受本轮前端发布影响。
