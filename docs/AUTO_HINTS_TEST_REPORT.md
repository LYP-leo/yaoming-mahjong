# 自动听牌提示与剩余张数测试报告

日期：2026-09-09。对应实现前计划：`AUTO_HINTS_PLAN.md`。

## 改动结果

- 默认展开并自动计算；有效座位进入牌局和牌桌版本变化后，200ms 合并连续更新，再获取本人听牌。打后听牌方案默认展开。收起只隐藏结果，不停止自动更新；同版本心跳不重算。
- 取消过期请求，校验请求代次、房间、玩家、令牌上下文及版本；换座、结算、卸载停止原计算。超前版本触发父页面同步，绝不把新分析配给旧手牌。
- 临时错误最多自动重试两次（1s、3s），冷却和耗尽预算跨版本保留，避免机器人连续变版造成请求风暴。成功、换身份或主动重试后重置。400/401/403/404 不持续重试。
- 每张进张牌下方直接显示 `N张`。0 张保留，并显示“四张均已可见”；番数、自摸/点和门槛及舍牌限制继续显示。
- 计数使用已有后端 `unseenCount`，没有修改后端生产代码或牌面。未知剩余张数包含可能在对手手中的牌，不是牌墙实际张数。

### 定向覆盖

- WAIT/DISCARD 两种模式下，五条的三张公开牌 → 1张，四张公开牌 → 0张。对应夹具本人没有五条；保留自摸 4 番、点和 3 番的门槛说明。
- 被碰的实体牌同时存在牌河和副露时只扣一次；假设弃出第四张后仍为 0张；更换对手暗牌/牌墙不影响计算，隐藏列表在读取时直接抛错的测试仍通过。
- 自动首次请求、阶段拦截、同版本心跳、连续版本合并、收起期间更新、迟到响应、取消、换令牌、换房间、卸载、终局。
- 重试冷却与预算在机器人持续更新中不重置；鉴权失败不请求风暴；身份/版本错配拒显并同步；WAIT 和 DISCARD 均保留 0/1 张、低番与点和限制。

## 浏览器验收

使用现有内置浏览器。`browser-act` CLI 及 `uv` 当前不存在，未安装额外工具。

本地 `hints-preview.html` 独立开发入口挂载真实 HintsPanel/WaitTiles/TileView，响应使用明确标记的测试夹具，不代表随机实战和牌；后端真实计数由 Java 测试验证。该入口不进入生产 dist。

- 无点击加载后自动出现“已自动更新”，请求计数为 1。
- 同版本心跳后请求仍为 1；模拟公开新牌后自动请求一次，五条由 1张变 0张。
- 收起期间继续分析，展开可直接看到新版本结果及默认展开的打后听牌方案。
- 390px 窄屏：页面 scrollWidth = 390，无横向溢出；数字位置在对应牌面底部下方 5px，1张/0张可见；桌面亦完成视觉检查。
- 模拟一次网络失败：初次正常请求加失败/自动重试共 3 次，未点击重试按钮，页面自行显示版本 2 的结果。

开发夹具热更新时一度因旧夹具卸载恢复 adapter，产生本地 404；完整重新加载后重新验收通过。这是独立夹具热更新的限制，不是生产 API 或前端构建故障。公网浏览器首次选择页面因控制工具超时失败，延长单次工具超时后成功；HTTP 下载本身返回正常。
