# 九数齐不得含字牌：修正计划

日期：2026-09-09，编码前记录。

## 已确认规则

用户明确九数齐不能包含东、南、西、北、白、发、中。判定范围为完整和牌，包括暗手、雀头和所有副露（吃、碰、明杠、暗杠、加杠）。当前要命麻将本就不使用北风；不为本次修复加入北风或更改牌组。

保留九数齐原有条件：包含 1 至 9，且每种数值只能归属一个面子或雀头；仍为 4 番。含字牌时只取消九数齐，不否定本来合法的牌形或其他独立成立的番种。

## 实施与验证

1. 计番器加入无字牌条件，同步服务端番种说明。规则手册与结算沿用真实服务端番种，不另造前端计番。
2. 回归包含六种在用字牌的雀头/刻子及各类副露，正向纯数牌、数值重叠与缺数仍按原规则。北风仍作为牌组外无效牌拒绝。
3. 检查引擎、听牌、机器人共享计番器的实际资格与番数；重点验证原来依赖错误九数齐达到 4 番的手牌现在不可点和，而其他合格牌仍可和。
4. 检查正在恢复的旧响应选项是否可能保留失效 WIN，防止旧窗口绕过新计番条件；如发现漏洞，在修改前补充具体计划。
5. 全量前后端测试和构建、必要实际接口与浏览器规则页验证，记录 NINE_RANKS_NO_HONORS_TEST_REPORT.md。发布使用上轮已获用户授权的直接重启方式，先备份并保留房间/牌谱，不清空数据，不改 FRP/Nginx。

## 旧响应窗口补充（该补丁编码前记录）

已确认旧窗口可能保留仅靠错误九数齐够番的 WIN，结算异常前清空 window 会导致卡窗。恢复时对未过期/已过期窗口都移除已失效 WIN，已提交但不再够番的 WIN 按过处理；其他已提交且仍合法的 WIN/吃碰/过保留，不重新开放已提交响应。新增合法 WIN 仍只允许未过期且未响应。展示动作与最终响应仲裁再复核点和资格，避免旧选项绕过或造成空窗口异常；对失效申请记录规则更新原因，不延长时间。已结束结算/历史牌谱不追溯改分。
