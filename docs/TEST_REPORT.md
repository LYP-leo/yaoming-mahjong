## 5. 测试中发现并修复的问题

- Java 26 超出当前 Byte Buddy 默认支持范围，Mockito 无法创建测试替身。测试进程增加实验兼容开关后通过；生产代码不受影响。
- TypeScript 构建初次缺少 Node 类型和 ESNext 资源类型。补齐类型依赖与编译配置后通过。
- `vue-tsc -b` 初次在源码目录产生编译 JS，导致 Vitest 重复执行。启用 `noEmit` 并清理生成文件后，恢复为单一测试源。
- 自动解散规则下，和牌后客户端继续读取已删除房间并显示 404。现已在检测到房间移除时清理会话并返回大厅，并添加回归测试。
- 圈数与目标分最初只有配置字段。现已纳入每局结算：达到圈数或目标分才结束整场，并按房间规则留房或自动解散。
- 浏览器实测发现 SockJS 在 Vite 环境引用未定义的 Node `global`，造成首页空白。已在 Vite 配置映射至 `globalThis`，修复后大厅正常渲染且 WebSocket 实时同步通过。
- 浏览器从 `127.0.0.1:5173` 访问时，后端原 CORS 白名单只允许 `localhost`，建房 POST 返回 403。现已允许两种本机地址，并添加回归测试。
- 玩家离开或身份过期后，旧标签页可能停留在房间并提交空 `playerId`；同时房间 WebSocket 订阅没有解除。现已验证查看者成员身份、清理失效会话并管理订阅生命周期。
- 建房/加入失败会展示错误，但 Promise 拒绝未处理并污染控制台。现已捕获预期错误；无效房号、重复昵称、满房和空规则测试时控制台保持干净。
- 规则编辑器遗漏“每种牌张数、封顶番、目标分”三个已有规则字段；现已全部补到界面。
- `maxFan` 原先未参与计分；现由和牌规则提供番值，并按封顶番计算自摸得分。
- 起手牌允许设置为无法形成和牌结构的张数；现强制满足 `3n+1`，前后端都有校验。
- 第二位玩家的座位在右侧而手牌在底部，视角不一致。现按查看者旋转座次，自己始终在底部，双人对手在正上方。
- 尚未摸牌时“和牌”和“打出”可被启用，只能依赖服务端报错。现仅在手牌为“起手牌 + 1”时启用。
- WebSocket 重连后没有主动校验当前房间，内存服务重启会留下过期牌桌。现于每次连接成功时重新加载大厅和房间；实测服务重启后自动返回大厅。
- 特殊番原先先于基础和牌合法性检查，理论上可能让不合法牌型凭“杠上开花/海底”附加番通过。现先要求基础和牌型成立，再追加宝牌和特殊番，并增加错误牌型回归。

## 10. M2-A 吃碰杠与放铳回归

自动化固定牌例覆盖：

1. 无人可响应时自动进入下一玩家摸牌；候选玩家“过”后弃牌保留并关闭响应窗口。
2. 下一家使用指定的两张手牌吃牌，生成公开顺子副露，暗手由 13 张变为 11 张并取得出牌权。
3. 碰牌消耗两张同牌，明杠消耗三张同牌并补摸一张；副露后按 `13 - 3 × 副露数` 校验暗手。
4. 吃碰后不能误判为自摸；只有正常摸牌或杠后补牌才能调用自摸。
5. 放铳使用完整牌型判定，基础点不乘自摸倍率，且只由出牌者支付。
6. 多人响应在全部候选提交后统一裁决，固定牌例验证“碰优先于吃”；同级按出牌者后的座次距离排序。
7. 房间规则可以独立关闭放铳、吃、碰、杠；关闭后即使牌例满足也不会打开响应窗口。
8. REST `claim` 请求校验、重复响应、非候选响应与无响应窗口操作均由服务端状态保护。

## 12. M2-C 多人和牌与响应托管回归

自动化固定牌例覆盖：

1. 三人牌局中两名候选同时荣和：开启一炮多响后两人各获得 500 点，出牌者合计支付 1000 点，`winnerIds` 按座次保存两名赢家。
2. 同一牌例关闭一炮多响后执行截和：仅出牌者之后最近座次获胜并获得 500 点，第二名候选不计分。
3. 两名玩家同时抢同一张加杠牌时均能获胜并分别计分；正式结算前原碰保持不变。
4. 弃牌响应窗口返回服务端截止时间；一名玩家已和、另一名未响应时，到期只为未响应者补“过”，保留已提交的和牌。
5. 同一超时任务连续执行两次不会重复计分；房间已完成裁决后后续扫描保持幂等。
6. 加杠抢和窗口到期后自动完成加杠、升级副露、补牌并保持出牌权。
7. 玩家打开响应托管后，新出现的碰/杠/和候选立即由服务端代过；在响应窗口中途开启托管也会立即代过并继续裁决。
