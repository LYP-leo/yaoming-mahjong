## 训练与续训的实际运行

1. 三人短 PPO 自我对弈 128 个学习决策，保存成功。
2. 三人、四人 CLI 测试各训练 256 步，再从检查点续训到 320 步；模型参数继续变化，优化器恢复，历史检查点与最终文件存在。
3. CLI 测试中三人模型对启发式机器人评估 3 场、四人评估 4 场，覆盖完整座位轮换，均完成真实结算。
4. 对现有机器人模仿预热 1,024 个各座位决策，交叉熵有限，生成可加载预热权重。
5. 预热权重通过 `--init` 开始三人 PPO，对启发式对手训练 2,048 个学习决策。两个采样段产生非零净分差奖励，合计完成 22 场；梯度和损失有限。
6. 四人默认小网络、8 环境、128 horizon、256 minibatch、4 epoch，自我对弈 2,048 个学习决策，完成 8 场，均流局、均分 10。这正说明“程序正常训练”不能等同于“已经学会赢牌”。
7. 非空运行目录拒绝覆盖；三/四人错误续训配置拒绝；模仿检查点不允许直接当 PPO 续训，但可以作为新实验的 `--init`。
8. SIGINT 两段逻辑通过单测：首次请求安全边界停止，第二次中断不发布半更新。未在真实 3060 Ti 控制台长训练中实测 Ctrl+C。

默认大小网络 CPU 的短训练日志约为每秒 600～800 个学习决策，指训练循环的环境推进、对手推理、采样和参数更新；不包括解释器/JVM初始化，且仅几秒样本、有并行测试负载。**不能用它承诺用户机器的 GPU 吞吐、训练工期或棋力。**

## 关键数学与安全回归

- 非法动作概率恰为零，全零终局掩码禁止送进策略采样。
- 同一学习座位的前后状态才构成 transition；其他人的行动产生的结算也归入该 transition。
- 终局不 bootstrap，不把下一场初始分数或零决策场的奖励算进上一场。
- GAE 不跨 episode 传播；旧策略 log probability 和 mask 不被更新修改。
- 有限损失和有限梯度；参数确实更新；冻结对手保持冻结直到指定更新边界。
- checkpoint 使用 restricted `weights_only=True`，保存模型、优化器、冻结对手、配置和随机状态；指纹不兼容拒绝。
- bridge 仅加载清单中校验过的 JAR，不使用可加载额外文件的 `lib/*` 通配 classpath。
- 构建测试通过之后才替换原模拟器；测试失败不会先覆盖之前可用的 JAR。

已将候选包解压到不包含原项目 `backend` 的独立目录，清空 `PYTHONPATH`，确认导入的 `yaoming_rl.__file__` 位于解压目录，并完成：

- `doctor --device cpu`：Java 21、两套规则、模型前后向检查通过。
- 四人 CPU PPO 训练 64 步，从该目录 checkpoint 续训到 96 步，成功。
- 对启发式机器人完成四个座位的 4 场评估，共 20 个单局、373 个学习玩家决策；真实结算完成。该未充分训练模型和牌率为 0，不作为强度证明。
- 不依赖原项目源码，直接运行包内 `build_simulator.py --test`，从随包快照重新编译成功，10 场 Java 测试和全部断言再次通过，规则/适配器指纹保持一致。

最终压缩包使用相同已验证源码和模拟器，另补录本测试结果。包内没有上述烟测产生的权重或评估文件。

## 复现命令

```powershell
python build_simulator.py --test
python -m pytest -q
python -m yaoming_rl.doctor --device cpu
```

GPU 机器另执行 `doctor --device cuda`，再按安装文档做短训练。完整安装和 GPU 验证由用户目标机器完成，失败时应保留错误输出排查。
