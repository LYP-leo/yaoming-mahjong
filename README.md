# 要命麻将

本项目由 GPT-6 Astra Ultra 构建

试玩链接：[要命麻将网页端](http://82.156.207.98:5173)

## 说明

创建房间可以选择“三人版”或“四人实验版”，房间创建后规则固定。三人依据[《要命麻将规则集.docx》](https://pan.baidu.com/s/1iabzA2EJUNCvPDvvPgYZFQ?pwd=ws3s)：108 张牌、万子仅一五九且 159 万可组成顺子、东南六局、4 番起和。四人依据[《要命麻将规则集 - 四人实验性.docx》](https://pan.baidu.com/s/1MrG5RJN1s6UkCtsATjBGWg?pwd=g4ix)及用户最新调整：136 张标准牌、正常万子顺子、东南八局、门清 1 番、全不靠 2 番且不承认风龙，改为 3 番起和。两版均每家 10 点、8 番封顶、任意一家归零终场；点和付人数倍番数，自摸其他每家付一倍，最多付至零。

四人全不靠只可加不求人或杠上炮，2 番本身不能和，加其中 1 番达到 3 番后可以和，不叠加门清。旧三人房间保持 4 番；已完成结算和旧牌谱不重新计番。最初四人实施见 [四人规则计划](docs/FOUR_PLAYER_RULES_PLAN.md) 和 [四人规则测试报告](docs/FOUR_PLAYER_RULES_TEST_REPORT.md)；随后门槛调整见 [3番起和计划](docs/FOUR_PLAYER_THREE_FAN_PLAN.md) 和 [测试报告](docs/FOUR_PLAYER_THREE_FAN_TEST_REPORT.md)。

## 开始一局

1. 启动后端与前端后，打开 [本地首页](http://localhost:5173/)，填写昵称、选择规则并创建牌局；创建弹窗可打开所选规则详情。
2. 房主可添加机器人填补空位，也可邀请朋友用房间号加入；三人版需要三家、四人版需要四家入席并全部准备才开局。机器人按本房规则选牌，主动托管仍为纯摸切。
3. 轮到自己时默认自动摸牌，可从顶部“设置”关闭。出牌、吃碰杠和和牌仍由你选择；默认第一次点牌选中，再点一次或按出牌按钮确认，可开启“快捷出牌”。结算默认展示赢家完整手牌、副露、和牌张及逐项计番依据；全部确认或等待 60 秒后继续下一局，终场主动确认后返回大厅。
4. 听牌区自动分析；没有可和进张时留空，有进张时显示牌面、未知剩余张数（包括 0张）及有效和牌番数。点和与自摸番数不同则分别标注，相同则合并。同局刷新期间保留原牌面，结果改变才更新，无需点击计算。“牌谱复盘”可以逐步查看本场已结束的小局，并导出 JSON。
5. 摸到的牌默认选中，但不会自动打出。牌桌支持 A / D 循环选牌（包括独立摸牌），Enter 或空格打出当前选中牌；出现鸣牌响应时空格仍是直接过。输入框、弹窗、托管和过期状态不执行游戏快捷键。鸣牌选项在手牌下方全宽排列，牌河单行显示；大量弃牌可点“查看全部”。
6. 复盘与对战共用牌桌布局，按历史规则展示三家或四家牌面，可选择下方手牌视角。滚轮向下看下一步、向上看上一步；表单、弹窗与缩放手势保留原行为，首尾步允许正常滚动页面。复盘不会执行出牌或确认结算。
7. “规则手册”可切换两套规则，列出对应牌组、20 个番种及结算口径。“我的座位恢复码”可用于关闭页面或换设备后恢复原座位。

项目现仅保留要命麻将。旧版入口、专属前后端代码、接口与依赖已移除，旧查询参数不再切换玩法。历史文档和备份仅作恢复参考，不表示当前功能。

## 退出与无人房间回收

- 等待时“退出房间 · 返回大厅”会真正释放座位，不是暂离；成功后才能清除本标签页身份。房主退出会把房主交给剩余真人并重置真人准备状态。
- 对局中仍可选择暂离保留身份，或确认离开由机器人接管；暂离后的大厅入口也能明确“退出原房间”。离开失败保留身份以便重试，不会假装已经成功。
- 机器人与已退出玩家不计入真人；真人连续60秒没有联系服务器后视为离线。在线的托管真人仍保护房间。没有真人后默认保留10分钟，之后销毁等待、进行中或终场房间；无人期间暂停推进，不让机器人无限续命。
- 真人重连或重新加入尚未到期的空等待房，会取消无人倒计时。空等待房的新真人接任房主。已有倒计时保存到快照；普通旧房重启后有重连宽限，不会重启即误删。
- 房间销毁前仅归档已结束小局，沿用最近20场及原参赛身份鉴权；未完成的小局不会编造结算。重要牌谱请及时导出。
- 服务端配置 `mahjong.rooms.empty-retention-ms`（默认600000毫秒）控制无人保留期；该配置影响当前房间回收，不改变三人/四人牌局规则。

实现计划见 [房间退出与回收计划](docs/ROOM_EXIT_EXPIRY_PLAN.md)，验证记录见 [测试报告](docs/ROOM_EXIT_EXPIRY_TEST_REPORT.md)。

## 新版实现与规则口径

- 后端为独立 `com.mahjong.yaoming` 模块：计番器、房间状态机、机器人、持久化与每位玩家的私有视图分离。接口前缀 `/api/yaoming`，前端目录为 `frontend/src/yaoming`。
- 服务端决定合法动作、抢牌仲裁和结算；前端按版本同步快照。房间、牌墙、手牌、响应窗口和结果保存在 `backend/data/yaoming-rooms.json`，恢复码不可与他人共享。
- 新规则新增平和 1 番：四顺子加数牌雀头，允许副露，159 万也算顺子，不附加门清或听口条件。门清改为 2 番，暗杠仍保留门清；断幺不再计番；清全带幺按新总表与附录统一为 3 番，仍排除混全带幺。清一色仅限一种数牌花色；字一色不再叠加清一色，仍排除混全带幺、碰碰和及番牌。番种总数仍为 20。
- 规则页、听牌、结算和机器人统一使用服务端计番。已完成的结算与旧牌谱保留当时番数、支付及明细，不按新规则重算。历史计划和报告中的旧番值仅作追溯，当前修订计划见 [新版规则同步计划](docs/RULEBOOK_2_UPDATE_PLAN.md)。
- 花牌版本未提供完整内容，当前只实现无花“朴素规则”。终场积分公式缺失，当前按剩余点数排名，同分按初始风位排序。
- 本次参考 [salasasa](https://salasasa.cn/) 的模块分层与牌桌区域设计，代码独立实现，未复制其[源码](https://github.com/xelnagamiao/open_mahjong_unity)、品牌或资源，也不连接其游戏服务。

实施范围与规则映射见 [要命麻将计划](docs/YAOMING_PLAN.md)，验证记录见 [要命麻将测试报告](docs/YAOMING_TEST_REPORT.md)，参考依据见 [salasasa 研究记录](docs/SALASASA_REFERENCE.md)。

## 第一批体验与稳定性优化 · 2026-09-07

- 摸牌 15 秒、出牌 30 秒、响应 20 秒、局间结算 60 秒，由服务器权威计时并持久化；轮询不续时。摸打超时自动托管，即使页面在线也会生效；主动“收回控制”才能取消超时托管。
- 新摸的牌独立放在手牌右侧；仅本人取得摸牌实体 ID。最新弃牌显示供牌人并高亮牌河，被吃碰杠或和牌取走后标记“已被取走”。
- 默认选牌再确认，快捷出牌开关保存在本机。切换轮次、手牌或合法动作变化会清除陈旧选择；普通心跳不干扰选牌。
- 手机使用紧凑双对手区和底部固定操作区，仅手牌局部可滑动；320px/390px 已做浏览器视口验收。
- 托管切换、明确离席遇到版本冲突时最多安全尝试 3 次；摸打、吃碰杠等不盲目重试。倒计时采用快照实际接收时刻校时，离线后切回页面不会凭空延长时限。

本批计划见 [优化计划](docs/YAOMING_OPTIMIZATION_01_PLAN.md)，完整结果见 [优化测试报告](docs/YAOMING_OPTIMIZATION_01_TEST_REPORT.md)。听牌辅助、牌谱复盘和实时推送已在以下第二批实现；分房持久化、HTTPS 与账号体系仍待后续建设。

## 第二批听牌、复盘与实时推送 · 2026-09-07

- 听牌辅助只展示满足自摸或点和门槛的进张牌、牌下余张数与有效番数，0张保留。未知剩余张数扣除本人手牌、所有牌河和公开副露，可能仍在对手手中，不是牌墙实际数量。后台更新保留现有结果，可见内容相同不重绘；换座、换局和结算清空。网络失败静默退避重试，不显示跳动文字。最新修正见 [滚动区域与听牌番数报告](docs/SCROLLBARS_HINT_FAN_TEST_REPORT.md)。
- “牌谱复盘”记录开局和动作后的三家牌面、牌河、副露、点数与结算，支持分局选择、单步、首尾、滑块、自动播放及 JSON 导出。仅本场参赛者可读取已结束小局，正在进行的小局不会公开对手暗牌；复盘不会暂停真实对局或自动替玩家操作。
- 离开房间后仍可从本机历史身份取回已完成牌谱。服务器保留最近 20 场已归档牌谱，本机最多保留 20 个参赛身份，请勿在公共设备保留恢复凭据。更新前未记录的旧局无法补齐；中途恢复的记录会标记不完整。导出包含参赛昵称与三家牌面，不含恢复码或牌墙顺序。
- 实时推送使用带请求头鉴权的 SSE，仅通知房间版本，客户端再取得自己的私有视图。落盘成功后才通知；正常时每 10 秒安全同步，断线后自动重连并回退到 2 秒轮询。Nginx 已关闭推送缓冲，沿用现有 FRP 前端入口。
- 牌谱与房间通过同一原子快照保存，写入失败一起回滚。本批未切换分房数据库，长期大规模使用仍需进一步拆分持久化与负载测试。

## 第三批结算、自动摸牌与参考牌面 · 2026-09-08

- 赢家的完整手牌和副露默认展开，和牌实体在手牌中只标记一次；暗杠结算时全部翻开。旁边显示服务器给出的番型、各项番数、说明、原始总番和封顶后计番。桌面并排展示，手机上下排列，确认按钮留在详情滚动区外。
- “设置”可切换默认开启的自动摸牌，以及默认关闭的快捷出牌，保存在本机。自动摸牌仅用于本人合法摸牌回合；查看规则/牌谱/结算、打开设置或离席窗口时暂停，但牌局倒计时继续。不会自动出牌、吃碰、和牌或确认结算；网络失败后可手动重试，不会持续重复提交。

- 手牌、牌河、副露、结算、规则和复盘共用相同 SVG 组件，保持原图案与比例。暗牌不渲染实际牌面。保留上游 M+ 许可及来源说明，生产分发文件在 `third-party/mahjong-graphic/`，运行时不依赖 GitHub 或外部图床。

## 智能练习机器人 · 2026-09-09

要命麻将的练习机器人，以及玩家明确离开房间后的机器人接管，使用智能策略。它会比较向听（离成牌还有多远）、扣除已知牌后的有效进张，以及正式计番器确认的可和等待（三人4 番、四人3 番）；三人支持159 万和风龙，四人支持普通万顺和全不靠，不误用七对子规则。合法和牌始终优先。主动、超时和离线托管已独立改为下述纯摸切，不再共用智能选牌策略。

吃碰先模拟后续出牌和够番前景；暗杠/加杠不再无条件执行，以免拆掉有效牌形或风龙。简单防守仅使用对手公开副露和牌河，低分且远离听牌时更谨慎。机器人不读取对手暗牌或牌墙内容；它不是训练模型或专业棋力 AI，远期番型判断仍是启发式估计。

实现前计划见 [机器人升级计划](docs/SMART_BOTS_PLAN.md)，实际后端/整场对战/隔离 HTTP 测试和服务器更新记录见 [机器人测试报告](docs/SMART_BOTS_TEST_REPORT.md)。

## 现有服务器部署

首次安装服务单元时，将仓库中的单元文件安装到 systemd 后再启用；后续更新构建完成后重启后端：

```bash
sudo install -m 644 deploy/mahjong-backend.service /etc/systemd/system/mahjong-backend.service
sudo systemctl daemon-reload
sudo systemctl enable --now mahjong-backend.service
sudo systemctl restart mahjong-backend.service
sudo systemctl status mahjong-backend.service --no-pager
```

切换服务前应停止先前手动启动、占用同一后端端口的进程。部署结果及公网验证以测试报告中的实际记录为准。

前端更新需要构建后发布（不再自动热更新）：

```bash
cd frontend
npm test
npm run build
sudo cp -a dist/. /var/www/mahjong-yaoming-20260907/
sudo chmod -R a+rX /var/www/mahjong-yaoming-20260907
```

日常增量发布保留仍在使用的新版本哈希资源；本次按要求移除旧版专属及旧构建资源，先备份再清理，可刷新页面取得仅新版构建。Nginx 配置见 `deploy/nginx-mahjong.conf`，修改后运行 `sudo nginx -t` 再重载。本次发布脚本将旧源码、静态资源及原 `/var/www/mahjong` 站点移入服务器 `backups/stable-table-new-only-20260909` 私有恢复目录，不删除房间数据；实际执行情况见本次测试报告。

## 本地运行与测试

需要 Java 21+ 完整 JDK、Maven 和 Node.js。

```bash
cd backend
mvn clean test
mvn spring-boot:run
```

另开终端：

```bash
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

前端 `/api` 代理本地 8080；新版使用 SSE 通知，不需要 STOMP/SockJS 或 `/ws`。房间数据路径可通过 `MAHJONG_YAOMING_FILE` 配置，默认为启动工作目录下的 `data/yaoming-rooms.json`。不要在运行中清空数据或替换被占用的 JAR；发布前检查房间并备份。

```bash
cd frontend
npm test
npm run build
```

## 手切与摸切 · 2026-09-09

牌河中的摸切牌下方显示短横杠，手切不加横杠。服务器按实际牌的实体 ID 判断：打出刚摸到的那张是摸切，打出原有手牌是手切；即使两张牌图案相同也分别判断。吃碰后的弃牌为手切，杠后补摸按实际打出哪张判断。真人、机器人和托管一致，三家牌河、最新弃牌及牌谱复盘同步显示，JSON 导出也保留记录。历史牌谱没有该信息时不猜测补标。

实现前计划见 [手切 / 摸切计划](docs/DISCARD_KIND_PLAN.md)，实际测试与发布情况见 [手切 / 摸切测试报告](docs/DISCARD_KIND_TEST_REPORT.md)。

## 纯摸切托管与中央状态条 · 2026-09-09

开启托管后自动摸牌并打出刚摸到的同一张实体牌；不吃、碰、杠或自动和牌，遇到响应自动过。超时 / 离线托管使用相同逻辑。吃碰后没有刚摸牌时开启托管，会固定打出按手牌排序的最右一张合法牌以继续牌局，该张如实记为手切，之后恢复摸切。收回控制后由本人决定动作。练习机器人和明确离席后的机器人接管仍保留智能策略。

中央“最新弃牌”区域保持固定高度，不产生内部滚动条；长昵称单行省略并保留完整悬停名称。牌河、日志等正常滚动区不受影响。实施计划见 [纯摸切托管计划](docs/TRUSTEE_TSUMOGIRI_PLAN.md)，实际验证与发布见 [测试报告](docs/TRUSTEE_TSUMOGIRI_TEST_REPORT.md)。

## 取消错误加入的振听限制 · 2026-09-09

要命麻将没有舍牌振听或过和振听：自己打过的同种牌可以点和；放过一次有效点和后，下一次别人打出同种牌，未摸牌也可以点和。仍须满足合法和牌结构、4 番起和及当前可响应条件。旧存档中的相关历史字段不再限制和牌。听牌辅助和机器人使用相同规则，机器人也不再把对手打过的牌视为绝对安全牌。

历史计划和测试报告中的旧限制描述仅保留为追溯记录，规则以此次修正为准。编码前计划见 [取消振听计划](docs/NO_FURITEN_PLAN.md)，实际测试与发布结果见 [测试报告](docs/NO_FURITEN_TEST_REPORT.md)。

## 九数齐无字牌条件 · 2026-09-09

九数齐要求完整和牌不得含字牌，包括雀头和全部副露（碰、明杠、暗杠、加杠）。仍须包含 1～9，每种数值只归属一个面子或雀头，计 4 番。含字牌时不计九数齐，但其他成立的番种照常计算；不足 4 番不能和牌。当前牌组依然不使用北风。修正计划见 [九数齐计划](docs/NINE_RANKS_NO_HONORS_PLAN.md)，验证与发布见 [测试报告](docs/NINE_RANKS_NO_HONORS_TEST_REPORT.md)。
